


我做了一个测试，在BaseActivity中，如果父类存在    @Inject属性，这个时候父类使用@AndroidEntryPoint标记，就会在父类和子类都被注入一次，如果只在子类使用@AndroidEntryPoint，父类不使用@AndroidEntryPoint ，子类也是可以正常注入的，这个时候父类要想使用某些注解是不是使用EntryPoint.from的方式来更合理




根据你的测试和观察，如果只在子类（例如具体的 Activity）上标记 @AndroidEntryPoint，而父类（BaseActivity）不标记，那么 Hilt 会在子类生成依赖注入代码时自动注入父类中声明的 @Inject 成员，这样可以避免重复注入。

当父类也标记了 @AndroidEntryPoint 时，父类和子类各自生成的注入代码会各自注入一次，导致同一个依赖可能被注入两次，从而产生不必要的复杂性或潜在问题。

因此，如果你希望 BaseActivity 能使用依赖注入，但又不希望在整个继承链上重复注入，一种更合理的方式是让 BaseActivity 不直接标记 @AndroidEntryPoint，而是在 BaseActivity 中通过 EntryPointAccessors 来手动获取依赖。这样可以：

- 避免在父类中重复生成注入代码；
- 保持注入逻辑集中在具体的子类上（例如在子类中标记 @AndroidEntryPoint，自动注入自身及其父类的依赖）；
- 同时又能在 BaseActivity 中使用所需的依赖（通过 EntryPoint.from 获取）。

所以答案是：
如果父类需要使用注入但又不想让它与子类重复注入，采用 EntryPoint.from 的方式在 BaseActivity 中手动获取依赖会更合理。这种设计既能利用 Hilt 自动注入的便利性，又避免了继承链中重复注入的问题。
